# Meta2DB composite shotgun source lead - not 84 qualified test studies

Live records read 2026-09-27: Zenodo v1 https://zenodo.org/records/17315984 ; original methods https://www.biorxiv.org/content/10.1101/2024.10.03.616398v2.full-text ; published article listing https://www.ovid.com/journals/bioinf/fulltext/10.1093/bioinformatics/btag422~meta2db-curated-shotgun-metagenomic-feature-sets-and . Zenodo reports 13,897 samples from 84 studies, 23 disease states and 34 geographies. Files listed there: 51.9 MB metadata CSV (published MD5 be523d58a63947765d728f1f4f89b07a), 420.9 MB profile zip (MD5 da6a26abecf2a951fbc7402fe8919e26), 46.1 MB lineage zip, 86.0 kB data definitions PDF and 40.7 kB metadata-field definitions spreadsheet. No file was downloaded or outcome scored in this screen.

The methods describe deliberate selection for Illumina WGS, public raw data/metadata, defined disease and a binary diseased/control label. They explicitly reuse some studies from curatedMetagenomicData and the iHMP disease repository. This is a harmonized composite with potentially duplicated source families, not 84 independent new cohorts for this digital-twin task. Disease classification is not subject trajectory, drug perturbation, species removal or causal intervention forecasting. Neither sample count nor disease label establishes repeated biological subjects, per-study units, patient baseline, treatment windows or same-task comparator eligibility. Study/source crosswalk, assay definitions, original permissions, license of deposited derived files and exact MGnify/other-candidate overlap require checks before reuse or leaderboard counting. The preprint's CC BY-NC-ND 4.0 refers to the preprint; do not silently apply it to the data. This is a breadth and metadata-workflow lead only, with zero admitted datasets/benchmark results.

This differs from the bioRxiv preprint's CC BY-NC-ND license; cite the deposit license only for its own deposited files, and still verify source-study use restrictions and human-data scope before redistribution. The 40,706-byte `meta2db_metadata_field_definitions.xlsx` was downloaded solely for outcome-blind dictionary inspection and matched its published MD5 `e84e51a92305cd8e1523c6cb9f8a5924`; it is not committed. The dictionary includes `host_subject_id`, `collection_date`, `days_from_first_collection`, `antibiotics`, `antibiotics_family` and repository `run_acc` fields. Those definitions establish *possible* columns, not their completeness or trustworthy subject/time/exposure linkage in any actual study. No 51.9-MB metadata rows or 420.9-MB abundance profiles were downloaded, and no study was admitted.

The pinned metadata CSV was downloaded and MD5-checked for an outcome-blind aggregate screen on 2026-09-27. It is Latin-1 encoded, 13,897 rows by 171 fields. `results/meta2db_metadata_screen.json` and `scripts/meta2db_metadata_screen.py` reproduce aggregate counts, with no row-level content checked in. There are 84 project_name labels but 197 project_id labels. All rows have a nominal host_subject_id; 807 project-name/subject label combinations recur (4,135 rows) across 22 project names, but this alone does not establish distinct people or independent longitudinal units. Only 1,246 rows across 9 named projects have populated `days_from_first_collection`, and only 262 project-name/subject label combinations repeat among these time-populated rows. The antibiotic-use field is populated on 7,401 rows, 472 marked TRUE; antibiotic-family data occur on just 77 rows. These fields are not course start/end or control labels. An explicit known mirror is `2022_American_Gut_Project`: 648 rows all under PRJEB11419, already present in the old MGnify audit at project level. No abundance profile was fetched, no score fitted, no study admitted. This is source metadata, not a benchmark.
