# Reliability evidence-vector type guard, 2026-09-27 23:56 IST

The unreleased Twin Reliability Index collector is intentionally unable to emit a 0-100 composite. Yet Python booleans are integers, so `value=True` could currently be recorded as accuracy 1.0; non-string source objects are coerced to printable text and could masquerade as provenance. Require finite real (not bool) component values and nonblank string source references. Restrict the optional domain to a nonblank string or `None`. Reject non-mapping or unknown component labels. Keep all existing verified numeric vectors and the unavailable composite unchanged. Unit tests cover booleans, empty/structured source and malformed domains. This is an input-integrity fix, not a calibration result, and it cannot certify a Twin Reliability Index.
